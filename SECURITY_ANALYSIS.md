# Анализ безопасности API Calculator

## 1. Используемые инструменты

В CI-пайплайн проекта интегрированы два инструмента безопасности:

- Semgrep — статический анализ исходного кода и файлов конфигурации;
- Trivy — анализ Docker-образа, системных пакетов и Python-зависимостей.

Проверки автоматически запускаются при каждом push в ветку main.

## 2. Результаты Semgrep

Semgrep выполнил статический анализ 7 файлов проекта.

Результаты проверки:

- проверено файлов: 7;
- выполнено правил: 329;
- обнаружено замечаний: 6;
- blocking findings: 6.

### 2.1 Использование изменяемых тегов GitHub Actions

В файле `.github/workflows/ci.yml` используются ссылки на GitHub Actions вида:

```yaml
uses: actions/checkout@v4
uses: actions/setup-python@v5
uses: aquasecurity/trivy-action@v0.36.0
```

Semgrep определил использование изменяемых тегов GitHub Actions как потенциальную проблему безопасности цепочки поставки.

В ходе анализа было обнаружено несколько ссылок на GitHub Actions по тегам версий, например `@v4`, `@v5` и `@v0.36.0`. Такие ссылки могут быть изменены владельцами соответствующих Actions, поэтому более безопасным вариантом является закрепление конкретной версии по commit SHA.

### Предлагаемое улучшение

Использовать полный commit SHA вместо изменяемого тега.

Пример:

```yaml
uses: actions/checkout@<COMMIT_SHA>
```
Это позволяет гарантировать использование конкретной версии GitHub Action.

### 2.2 Запуск Docker-контейнера от root

Semgrep обнаружил отсутствие инструкции `USER` в Dockerfile.

По умолчанию процесс внутри контейнера запускается от пользователя root. Это повышает потенциальные последствия компрометации приложения, поскольку процесс получает повышенные права внутри контейнера.

### Предлагаемое улучшение

Рекомендуется создать отдельного непривилегированного пользователя и запускать приложение от его имени.

Пример:

```dockerfile
RUN useradd -m -u 10001 appuser

USER appuser
```

После этого приложение будет выполняться внутри контейнера без прав root.

## 3. Результаты Trivy

Trivy выполнил анализ Docker-образа `calculator-api:1.0.3`.

Результаты проверки:

- уязвимости в системных пакетах Debian: 0;
- уязвимости в Python-пакетах: 2;
- HIGH: 2;
- CRITICAL: 0.

### 3.1 Уязвимость msgpack

Trivy обнаружил уязвимость `GHSA-6v7p-g79w-8964` в пакете `msgpack`.

Параметры уязвимости:

- установленная версия: `1.1.2`;
- исправленная версия: `1.2.1`;
- уровень опасности: HIGH.

Уязвимость связана с возможностью чтения за границами допустимой области памяти и аварийного завершения программы при определённых условиях работы с `Unpacker`.

### Предлагаемое улучшение

Рекомендуется обновить пакет `msgpack` до версии `1.2.1` или выше.

Пример:

```text
msgpack>=1.2.1
```

### 3.2 Уязвимость setuptools

Trivy обнаружил уязвимость `CVE-2025-47273` в пакете `setuptools`.

Параметры уязвимости:

- установленная версия: `70.3.0`;
- исправленная версия: `78.1.1`;
- уровень опасности: HIGH.

Уязвимость связана с Path Traversal в компоненте `setuptools PackageIndex`.

### Предлагаемое улучшение

Рекомендуется обновить пакет `setuptools` до версии `78.1.1` или выше.

Например, в Dockerfile можно добавить:

```dockerfile
RUN pip install --upgrade "setuptools>=78.1.1"
```

## 4. Итог анализа

По результатам работы Semgrep было обнаружено 6 замечаний. Основные выявленные проблемы связаны с использованием изменяемых тегов GitHub Actions и запуском Docker-контейнера от пользователя root.

Trivy обнаружил две уязвимости уровня HIGH в Python-пакетах `msgpack` и `setuptools`.

Уязвимостей уровня CRITICAL обнаружено не было. В системных пакетах Debian также не было выявлено уязвимостей.

Для повышения безопасности проекта предлагаются следующие меры:

- закрепить используемые GitHub Actions на конкретные commit SHA;
- запускать Docker-контейнер от непривилегированного пользователя;
- обновить пакет `msgpack` до версии `1.2.1` или выше;
- обновить пакет `setuptools` до версии `78.1.1` или выше;
- регулярно обновлять базовый Docker-образ;
- продолжать автоматический запуск Semgrep и Trivy при каждом push.
