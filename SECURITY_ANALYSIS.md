# Анализ безопасности API Calculator

## 1. Цель анализа

Цель данного этапа — встроить в CI-пайплайн автоматические средства анализа безопасности, выполнить проверки проекта при push в ветку `main`, проанализировать полученные результаты и предложить меры по снижению выявленных рисков.

В пайплайн были добавлены следующие инструменты:

- Semgrep — статический анализ исходного кода и конфигурационных файлов;
- Trivy — анализ Docker-образа, системных пакетов и Python-зависимостей на известные уязвимости;
- Syft — формирование SBOM, то есть перечня компонентов и пакетов, входящих в Docker-образ;
- Grype — анализ SBOM и поиск известных уязвимостей в найденных компонентах;
- Gitleaks — поиск секретов, токенов, паролей и других чувствительных данных в Git-репозитории;
- Checkov — анализ Dockerfile и GitHub Actions на небезопасные настройки.

Проверки запускаются автоматически при каждом push в ветку `main`.

## 2. Результаты Semgrep

Semgrep выполнил статический анализ файлов проекта.

Результаты проверки:

- проверено файлов: 8;
- выполнено правил: 329;
- обнаружено замечаний: 11;
- blocking findings: 11.

### 2.1. Использование изменяемых тегов GitHub Actions

Semgrep обнаружил 10 случаев использования GitHub Actions по тегам версий, например:

```yaml
uses: actions/checkout@v6
uses: aquasecurity/trivy-action@v0.36.0
uses: anchore/sbom-action@v0
uses: anchore/scan-action@v7
uses: gitleaks/gitleaks-action@v3
uses: bridgecrewio/checkov-action@v12
```

Такие ссылки считаются потенциальным риском безопасности цепочки поставки, поскольку тег версии может быть переназначен владельцем Action на другой commit.

### Предлагаемое улучшение

Использовать полный commit SHA вместо тега версии.

Пример:

```yaml
uses: actions/checkout@<FULL_COMMIT_SHA>
```

Это позволяет гарантировать использование одной конкретной версии GitHub Action.

### 2.2. Запуск контейнера от root

Semgrep также обнаружил отсутствие инструкции `USER` в Dockerfile.

По умолчанию процесс внутри контейнера может запускаться от пользователя root. Если приложение будет скомпрометировано, наличие повышенных прав увеличивает возможные последствия атаки.

### Предлагаемое улучшение

Создать отдельного непривилегированного пользователя и запускать приложение от его имени.

Пример:

```dockerfile
RUN useradd -m -u 10001 appuser
USER appuser
```

Trivy выполнил анализ Docker-образа:

- уязвимости в Python-пакетах: 4;

### 3.1. Уязвимость msgpack

Обнаружена уязвимость:

```text
GHSA-6v7p-g79w-8964
```

Параметры:

- пакет: `msgpack`;
- установленная версия: `1.1.2`;
- исправленная версия: `1.2.1`;
- уровень опасности: HIGH.

Уязвимость связана с возможностью чтения за границами допустимой области памяти и аварийного завершения при определённых условиях работы с `Unpacker`.

### Предлагаемое улучшение

Обновить пакет:

```text
msgpack>=1.2.1
```

### 3.2. Уязвимость setuptools

Обнаружена уязвимость:

```text
CVE-2025-47273
```

Параметры:

- пакет: `setuptools`;
- установленная версия: `70.3.0`;
- исправленная версия: `78.1.1`;
- уровень опасности: HIGH.

Уязвимость связана с Path Traversal в компоненте `setuptools PackageIndex`.

### Предлагаемое улучшение

Обновить пакет минимум до версии:

```text
setuptools>=78.1.1
```

### 3.3. Уязвимости urllib3

Trivy обнаружил две уязвимости уровня HIGH в пакете `urllib3`.

Параметры:

- установленная версия: `2.7.0`;
- исправленная версия: `2.8.0`.

Обнаружены:

```text
CVE-2026-97687
CVE-2026-97689
```

Первая уязвимость связана с перехватом трафика при определённой конфигурации TLS через HTTPS proxy.

Вторая связана с возможностью отказа в обслуживании из-за неограниченного выделения памяти при обработке chunked-данных.

### Предлагаемое улучшение

Обновить пакет:

```text
urllib3>=2.8.0
```

## 5. Результаты Grype

Grype выполнил анализ SBOM, созданного Syft.

В отличие от Trivy, Grype показал ряд уязвимостей не только в Python-зависимостях, но и в системных пакетах Debian.

Среди найденных проблем присутствовали уязвимости уровня HIGH, например в пакетах:

- `perl-base`;
- `libncursesw6`;
- `libtinfo6`;
- `ncurses-base`;
- `ncurses-bin`;
- `libc-bin`;
- `libc6`;
- `zlib1g`;
- `gcc-14-base`;
- `libgcc-s1`;
- `libstdc++6`;
- `util-linux` и связанных с ним пакетах;
- `libacl1`.

Для значительной части найденных уязвимостей Grype указал:

```text
(won't fix)
```

Это означает, что для используемой версии пакета в текущем источнике исправление не предлагается.

В конце проверки Grype сообщил, что были найдены уязвимости уровня HIGH или выше.

### Предлагаемые улучшения

- регулярно обновлять базовый Docker-образ;
- пересобирать образ после выхода обновлений системных пакетов;
- по возможности использовать более минимальный базовый образ;
- повторно запускать Grype после обновления базового образа;
- отдельно отслеживать уязвимости, для которых пока отсутствуют исправления.

Различие результатов Trivy и Grype не является ошибкой: инструменты используют разные базы данных, правила сопоставления и настройки фильтрации. Поэтому их совместное применение позволяет получить более полную картину состояния Docker-образа.

## 7. Результаты Checkov

Checkov выполнил проверку Dockerfile и конфигурации GitHub Actions.

### 7.1. Dockerfile

Результаты:

- Passed checks: 33;
- Failed checks: 2;
- Skipped checks: 0.

Обнаружены две проблемы.

#### Отсутствует HEALTHCHECK

Проверка:

```text
CKV_DOCKER_2
```

В Dockerfile отсутствует инструкция `HEALTHCHECK`.

Это означает, что Docker не имеет встроенного способа автоматически определить, отвечает ли приложение внутри контейнера.

### Предлагаемое улучшение

Добавить healthcheck для API, например проверку HTTP-доступности приложения.

#### Не создан отдельный пользователь

Проверка:

```text
CKV_DOCKER_3
```

Checkov подтвердил проблему, ранее найденную Semgrep: в Dockerfile отсутствует создание непривилегированного пользователя.

### Предлагаемое улучшение

Создать отдельного пользователя и использовать инструкцию:

```dockerfile
USER appuser
```

### 7.2. GitHub Actions

Для GitHub Actions получены результаты:

- Passed checks: 76;
- Failed checks: 0;
- Skipped checks: 0.

Checkov не выявил ошибок конфигурации GitHub Actions по применённому набору правил.

## 9. Предлагаемые меры повышения безопасности

По результатам всех выполненных проверок рекомендуется:

1. Закрепить GitHub Actions на конкретные commit SHA вместо изменяемых тегов версий.
2. Создать непривилегированного пользователя внутри Docker-образа и запускать приложение от его имени.
3. Добавить `HEALTHCHECK` в Dockerfile.
4. Обновить `msgpack` минимум до версии `1.2.1`.
5. Обновить `setuptools` минимум до версии `78.1.1`.
6. Обновить `urllib3` минимум до версии `2.8.0`.
7. Регулярно обновлять базовый Docker-образ.
8. Повторно анализировать образ после обновления системных пакетов.
9. Продолжать формирование SBOM через Syft.
10. Продолжать проверку SBOM инструментом Grype.
11. Продолжать автоматический поиск секретов через Gitleaks.
12. Продолжать проверку конфигурации через Checkov.
13. Сохранять автоматический запуск всех средств анализа при каждом push в ветку `main`.
